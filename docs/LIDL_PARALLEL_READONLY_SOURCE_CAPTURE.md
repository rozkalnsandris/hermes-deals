# Lidl concurrent-campaign read-only source capture contract (#906)

## Purpose and authority

The selected store `DE06664` exposes two concurrent official 2026-11-23..28 campaigns, `36518f/ar/10` and `cde58d/ar/21`. Neither the selected-store leaflet page nor reviewed Schwarz metadata establishes a unique weekly-grocery priority. After the advisory-only review PR #1201 and pure pre-captured source inspector PR #1202, this source-only work adds **bounded independent in-memory HTTP GET capture**. It is not an authority to select, classify as grocery, persist, ingest, deduplicate offers, run Gate A/B, or publish.

`backend/app/lidl_independent_campaign_capture.py` exports `capture_parallel_campaign_sources(client, ambiguity=..., binding=..., berlin_as_of=..., allowed_pdf_hosts=...)`. It returns `(report, evidence_by_campaign_identity)`; each `FlyerEvidence` value holds raw JSON/PDF bytes *in memory* keyed by `(flyer_identifier, route_region)`. The report includes SHA-256 content hashes, byte lengths, official flyer UUID, advertised API regions, exact dates, hashed viewer/API/PDF URLs, raw hub hash, hashed selected-store cookie context and per-candidate status. **No production paths import this function.** No source snapshot is written to disk, the corpus, DB or Review.

## Trusted inputs and preflight

1. Caller supplies a complete **preexisting `LidlFamilyAmbiguityError.review`**, with `decision=UNRESOLVED`, `review_required=true`, `selection_authorized=false`, no truncation, canonical slugs/dates and unique route-bound identities. The existing #1200/#1201 review validator enforces that it is applicable to Berlin `as_of` and **store `DE06664`**. The `StoreBinding` must equal the selected-store binding already modeled by the original source discovery. This is not permission to infer store identity from route `ar` or `region_id`.
2. Caller supplies a *fresh isolated* `httpx.Client` (production integration, if ever approved, must set `trust_env=False`, use normal TLS validation and a bounded timeout); the module rejects a client carrying `auth`, default `Authorization`, or `Proxy-Authorization` headers **before network access**. The caller also supplies an **independently reviewed exact-host allowlist** for official PDF CDN locations. The allowlist must never be constructed from the untrusted flyer API response. No real credentials/cookies, anonymous proxy/redirect overrides or broad wildcard hosts are necessary.
3. The module performs a single HTTPS GET to the fixed selected-store hub `https://www.lidl.de/c/online-prospekte/s10005610/` with a cookie header constructed from the exact `StoreBinding`. It parses the full hub candidate set and rechecks that a fresh `select_current_and_next` still yields **exactly the same BLOCKED ambiguity**; if the hub has changed, is missing, truncated, becomes unambiguous or differs by route/validity/identity, the operation terminates **before any per-campaign GET**.

## Independent per-campaign capture

- Every hub-validated identity gets its own fixed official viewer request at `/l/prospekte/<flyer-slug>/ar/<route>` using the explicit selected-store cookies; its HTML byte SHA-256 is recorded. The observed hub URL must use exact-host HTTPS `www.lidl.de` and the same identity-bound path; only a query or trailing-slash decoration is tolerated. Requests use the canonical query-free URL, never forward hub query parameters, and separately hash the observed href and canonical request URL. Different paths, fragments, off-host URLs and redirects remain rejected. This is a bounded source-contract compatibility fix, not proof of which viewer URL variation caused the 2026-11-21 LIVE failures.
- Every lane independently uses the fixed `https://endpoints.leaflets.schwarz/v4/flyer` API with `version=4`, `client=lidl`, `flyer_identifier=<lane-slug>` and **that lane's** `region_id=<lane-route>`. The API response is bounded (16 MiB), UTF-8 JSON with duplicate-key rejection. API validity, route advertised regions, canonical official flyer UUID, nonempty pages and PDF URL are validated *before* any PDF request.
- PDF GET occurs only if the source API URL is HTTPS, canonical, no userinfo/unsafe port/fragment, and its hostname exactly matches the caller-supplied **trusted PDF host allowlist** (no wildcard or IP literal). The document body is bounded to 256 MiB and must begin `%PDF`. Hub/viewer bodies are bounded to 2 MiB each. Redirects, non-200 status codes, empty, oversized or failing responses are **not** followed or retried; transport errors become stable per-campaign rejection codes.
- The API and PDF GETs receive an explicitly empty Cookie header. Selected-store cookies are scoped to the Lidl hub/viewer; they are not sent to the Schwarz API or CDN. No arbitrary URL discovered in HTML/JSON becomes an unverified network destination.
- Captures are independently validated by PR #1202's `inspect_independent_campaign_sources`. Two different campaign identities sharing one official flyer UUID are both quarantined; one failing lane cannot turn the other into an approved winner. The report is deterministic by identity (apart from the exact fetched hub bytes), and returns status/reason and provenance rather than raw bytes or signed URLs. The `evidence_by_campaign_identity` mapping contains raw captured bytes only in memory for any later *separately authorized* inspection.

## Immutable authority boundaries

The report always preserves `gate_a_result=BLOCKED`, `decision=UNRESOLVED`, `review_required=true`, `selection_authorized=false`, `collection_authorized=false`, `gate_b_authorized=false`, `corpus_write_authorized=false`, `db_write_authorized=false`, `publication_authorized=false`, `runtime_registration_authorized=false`, `write_performed=false`, `local_write_performed=false`, `origin_attested=false`. A successful HTTPS GET/hash comparison is not third-party verified origin attestation or a unique grocery classification. It cannot create `WAIT_SOURCE`, a Gate B artifact or permission to publish.

**Hard exclusions:** no execution against LIVE/RPi5, no worker/systemd/dispatcher changes, no write to source files/corpus/DB/Review, no production offer extraction, no integration into scheduled workflows, no merge without a subsequent exact-HEAD owner decision. A real RPi5 source fetch or any persistence/production action needs separately scoped authorization and evidence, even after a source PR passes CI.
